## 3. 本轮新增的框架改进项

### 3.1 切片行数不能直接当单文件行数传给下游

犯错的根源：`wave2a-sweep` 的 `line_count` 是**整个切片的总行数**，我在派发时把它当成了单文件行数写进任务书。

**规则**：派发深挖任务时，**必须现场 `wc -l` 取真实行数**，或明确标注「这是切片总量，单文件行数需现场确认」。**行数写错会让 agent 误判工作量，也可能导致它跳过本该审的文件。**

同理，`files` 列表也不能凭切片记忆写——`S25/assets/*.mjs` 根本不存在，是我凭上一轮切片的目录印象臆造的。

### 3.2 第四个 `animation ... both` 案例

S25-1 是这一形态的**第 4 次**出现（前三次：S08 / S16 / S22）。全仓已有 11 个文件有同类结构风险。

**这已经不是"偶发 bug"，是这个项目的架构级问题。** 建议修复时**统一处理**：把所有 `animation: ... both` 改成只在动画期间生效，或把状态类的 `transform` 移到独立元素上。
