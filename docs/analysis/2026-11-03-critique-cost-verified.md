## 二、它的反直觉结论：钱不是瓶颈

**这条是全部 13 份锐评里唯一一个"对我有利"的发现，而它是我自己从没算过的。**

> 用 token 账单来质疑这套框架是**站不住的**——这一点框架自己反而没算过。

**真正的瓶颈是**：

| 指标 | 值 | 问题 |
|---|---|---|
| **每交付一条可消费结论的 token** | round31：30M / 1 条完成修复 = **30M/条** | 极差 |
| **发现阶段的浪费率** | 124 条里 Skeptic 撤销 82 条（**66%**）| **2/3 的花费打在了最终不成立的结论上** |

**所以「用 AI 省时间」在 5 轮链上不成立**——省的是钱，不是时间。

## 三、它的核心诊断：「账算错了地方」

这是 10 条里最有力的一句，因为它把三个错误归到了同一个根因：

| 错误 | 表现 |
|---|---|
| **量错对象** | 用 agent 计数当 token 预算。用户说"token 不是约束"，框架的回应是**偷偷把 token 换算成 agent 数再当 token 用** |
| **量错形状** | 用**常数 60** 当发现数的函数。上游按切片数（可预测），下游按发现数（不可预测），塞进同一个常数 |
| **量错顺序** | 用 FIFO 当可达性筛选。可达性是**宽扫的输出**，而宽扫的**派发顺序**是 FIFO——**省钱机制在花完钱之后才生效** |

第三条我要单独说，因为它是**算术上证明无效**的。

### C5 · 「可达性省下 72% 预算」在算术上等于 0

```
1. 宽扫派发顺序 = FIFO（第 5 节第 2 条明文禁止按重要性排序）
2. round31 里死代码正好在前 40 片，因为它按目录聚合、目录名在字典序前面
   → 同一 FIFO 取 16，取到的仍是 fakefx 的头 16 片
3. reachability 由宽扫自己标 → 标记出来时，这 16 个 agent 的钱已经花完了
4. planned_sweep_agents 在波次二A 启动前冻结（:292），省下的 24 个深挖额度无法回流
```

**净效果**：

```
旧公式：40 片全宽扫 → 覆盖 40/85 = 47%
新公式：16 宽扫 + 24 深挖额度作废 → 覆盖 16/85 = 18.8%
```

**「72% 会被省下」= 0。浪费没被消除，只是从「用于不产出的工作」变成「不用于任何工作」。**

## 五、它给的最该砍的环节（我认为这是全部锐评里最可执行的一条建议）

**砍掉宽扫波。**

```
原：  1 recon + 16 sweep + 24 deep dive = 41（超 budget 1）
新：  1 recon(含 import 闭包) + 1 工具agent + 39 deep dive = 41

→ 宽扫 16 → 0，deep dive 24 → 39（+62.5%）
→ 覆盖率：16/85 宽扫 + 12/85 深挖 → 39/85 = 45.9% 深挖（回到旧公式 47% 的水平）
→ 且每一片都是**有证据链的产出**，不是 leads
```

**为什么不该砍别的**：

| 环节 | 理由 |
|---|---|
| **锐评** | **唯一在省钱的环节**：4 个 agent 撤销 82 条 = 每个节省 41 个下游 agent |
| **深挖** | 唯一的发现来源 |
| **修复/验收** | 已是可选路径；验收是唯一「没有上游善意假设」的门 |
| **侦察** | 1 个 agent 决定 40 个的去向，**唯一杠杆 > 1 的环节**；D9.1 实测证明它错了会让 89% 的项目蒸发 |

### 宽扫为什么性价比最差（三条独立证据）

1. **旧公式下它吃满 100% 的 discovery_budget（40/40），深挖额度 = 0**。而 40 个 agent 的产出被**三重降级**：不进报告正文、不进锐评、不判严重性。**89% 的 agent 产出了下游零消费的中间件。**
2. **新公式降到 16，但覆盖率从 47% 掉到 18.8%**，省下的 24 个额度因冻结规则作废。
3. **它做的事有 60–70% 是机械的**——reachability 是 import 闭包（"一个 import 图几秒钟就能给出"），6 维里至少 2 维是 `grep` + `comm` 可完成的。而 `wave2-audit.md` 自己就写着「标识符对账——**静态即可发现的最高性价比检查**」。

## 六、我的判断

**这份我全盘接受，因为它给的是可复算的算式，不是判断。**

而且它提供了 13 份锐评里唯一一个**"成本降 40%、覆盖率不降、产出质量上升"**的具体改动——砍宽扫换工具。

**但它也给了我最反直觉的一条**：

> **钱不是问题，时间才是。**

我一直在"不计 token"和"预算 60"之间纠结，**从没算过真实的钱**。算完发现：完整审计约 $164，人工要 $4,920–24,600。**差 30 倍。**

**真正的问题**是：
- 每交付一条结论 30M token
- 2/3 的花费打在最终不成立的结论上
- 5 轮链 50–80 小时 = 和人工同量级

**所以"太贵"不是砍功能的理由，"慢"和"低效"才是。** 而砍宽扫恰好同时解决三者。

**它这个结论与竞品分析、提示词工程师两份收敛到同一个点**：宽扫这类机械活该交给工具，不该交给 40 个 LLM agent。
