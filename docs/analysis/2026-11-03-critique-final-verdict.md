## 二、四条必须立刻修的（与所有其他问题独立）

这四条是**规则互相打架**，不是主观判断，不需要权衡：

### ① 没有角色被授权写产物

```
6 个 wrapper：只有 fix-worker 有 Write
所有模板：零处指示子 Agent 写文件
report-naming:97：主 Agent 不得写任何波次产物文件
final-report:153：找不到出处的条目删掉
```

**后果**：产物文件不存在 → `artifact_paths` 全空 → 报告结论表为空 → `run-state` 的"以产物目录重建"也失效。

**这是唯一一条会"静默产出一份格式完美、结论为空的报告"的缺陷。**

### ② 主 Agent 被禁止使用它被要求使用的工具

```
protocol:258   允许 spawn_agent / read_result / ... （无 Bash）
protocol:95    主 Agent 必须执行 git status | grep ...
```

**四处同族**：`git status` 自检、`wc -l` 核实行数、校验 `artifact_paths` 存在、从产物目录重建。

**改法（一行）**：`protocol:263` 已经说对了——"不得读取**源代码内容**"，对象是内容不是工具。白名单改成真实工具名 + 作用域。

### ③ 两个死锁

```
F1: 波次二门控要求全 SUCCESS，但 PERMANENT_FAILURE 是合法终态且禁止重派
    → 门控恒 false，无转换可救

F2: CONTRACT_VIOLATION 的 attempt 从头计数 → 无次数上限
    → 唯一出口是 60 的预算护栏
```

**F1 已经发生过**：round31 停在 `IN_PROGRESS`，我原先归因于"修复波拖累""预算不足"——**那些是表象，真因是门控要求一个不可能达到的状态。**

### ④ `direct_contradiction` 不在契约 + `UPHELD` 对 Skeptic 合法

```
wave3 有 5 处要求它是强制字段
output-contract 的 critique schema 零命中
→ 唯一防滥杀的证据，机械校验看不见

verdict 枚举三角色共用，只给 Arbiter 加了反向约束，Skeptic 一侧空白
→ 100% 返回 UPHELD 的 Skeptic 是合法的 SUCCESS
```

## 三、关于 Skeptic 那条「净收益为正」—— 我要分开处理

**它移除了 6 条主张，其中 5 条我接受。第 6 条要分开看。**

### 接受的部分

> 唯一被验证有产出的路径，是只有 2 个深挖 agent 的单遍流程。
> 后来加的波次（宽扫、可达性、裁量留痕、Arbiter、五波门控）**边际贡献是 0 条可核实发现**。

**这条我无法反驳。** 证据是硬的：

| 轮次 | 方法 | 可核实发现 |
|---|---|---|
| 第 1 轮 | 2 个深挖 agent，无宽扫 | 29 条（含 S04 阻断级） |
| 第 2 轮 | 5 组并行，直接深挖 | 52 条有产物 |
| **round31** | **唯一跑过完整五波次的** | **1 条修复、没有最终报告** |

### 但我要拆出它隐含的一个错误归因

它说「所有后来加的波次边际贡献是 0」。**这个因果不成立**，因为：

**那些波次从来没被真正跑过。** 两遍制在 round1 时还不存在（模板晚 12 小时），round31 的五波次跑的是**旧版**（维度轮转、无可达性标记）。

**所以正确的表述是「未验证」，不是「已验证为 0」。** 这两者有本质区别：
- 「已验证为 0」→ 砍掉
- 「未验证」→ 要么验证，要么按成本审计员的建议用工具替代

**但即便如此，Skeptic 的结论方向是对的**：在一个"未验证"的东西上继续加规则，是赌博，不是工程。

## 四、我要打折的两处

### 竞品分析的「72% 该删」

**它自己给的替换方案有前提没算**：换成 Semgrep/SARIF 意味着用户必须装并配置这些工具——直接违背"纯提示词、任何 harness、零依赖"的立身之本。

**但它的方向是对的**。打折后我接受的是：
- **该换工具的**：reachability（import 图）、标识符对账（`comm`）、模式复查（Semgrep 规则）、去重（SARIF fingerprint）、严重性定级（CVSS 向量）
- **「72%」这个数字**来自按行数线性估，没算换掉后连带失效的交叉引用（SARIF 一换，六角色分支、10 种 kind、裁决枚举全部重写）

### 重建者的「~1000 行」

**它低估了保留四块独有价值（语义入口、注释考古、承诺 vs 实现、减法归并）所需篇幅。**

**我倾向 ~1500–2000 行**：核心提示词 ~800 行 + 这四块各 150–250 行 + 必要的契约。

## 六、我现在的判断

### 这套框架值得继续吗？

**值得，但形态要变。**

**它的四块独有价值，13 份锐评里没有一份能否定：**

| # | 价值 | 被谁确认 |
|---|---|---|
| 1 | **语义入口判断**（`ENTRY` vs `UNREACHABLE`） | 竞品分析明确说"这一条确实是 LLM 的，别删" |
| 2 | **注释考古**（从修复注释反推缺陷形态） | 竞品分析说"全框架信噪比最高的入口" |
| 3 | **承诺 vs 实现**（散文与代码的错位） | 竞品分析说"占实测发现的 22%，零工具覆盖" |
| 4 | **减法与归并**（128 条收敛成 4 个根因） | 竞品分析说"工具的天然倾向是做加法，只有 LLM 会做减法" |

**而实测证据支持这个判断**：

你能看到的所有"好发现"都来自这四块——
- `--rot` vs `--r`（标识符差一个字母）→ 属于第 1 类的近亲
- `check-texture` 注释记录了 bug、`verify-prototype` 没修 → **第 2 类**
- M02 的 `PLACEHOLDER` → **第 3 类**（CSS 说它是规则，实际不是）
- 29 条归并成"状态漂移 25 / 文案 vs 实现 28" → **第 4 类**

**而 round31 那 45 个 agent，一条这样的发现都没产出。** 因为它们跑的是五波次的机械部分。

### 所以答案不是"删掉"或"保留"，是：

**把这个框架从"多 agent 审计流水线"改造成"LLM 判断层的四块能力清单 + 一个工具链"。**

```
工具链（先跑）：
  semgrep + tsc/编译器 + dependency-cruiser + Playwright + Stryker + SARIF 去重
  → 产出基线告警

LLM 层（只处理工具做不到的）：
  ① 语义入口判断
  ② 注释考古
  ③ 承诺 vs 实现的对齐
  ④ 把结果收敛成"修什么、不修什么"

编排：
  一个薄调度器（~200 行），不是 24 份提示词
```

**规模**：从 6114 行降到 ~1500 行 + 200 行代码。

**如果我继续"读锐评 → 修矛盾 → 再读锐评"，就是在重复它批评的那个循环。**
