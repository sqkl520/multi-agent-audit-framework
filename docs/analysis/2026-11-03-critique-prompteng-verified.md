# 框架锐评 · 第 4 视角（提示词工程现实性）· 已核实

> **16 条，全部是"这个要求模型做不到"。**
> 最狠的地方：它用**我自己的两次失效记录**证明我的核心假设不成立。

## 一、它的总前提（决定了后面每条的严重性）

> **`framework/` 下没有任何一行可执行代码**（`find` 只有 `.md`）。
> 所以"框架靠什么阻止"这个问题的答案是：**只有文字**。
> 下面所有机制的执行率，**等于执行该文字的模型在那一刻的遵从率**。

## 二、已核实：两条最致命的矛盾

### P-12 · 验收 Agent 被要求做写操作，但它是只读角色

**同一份文件里的三处，构成空集**：

```markdown
<!-- wave5-verify.md:32 -->
3. **不修改任何文件**。验收Agent是**只读**角色，没有任何写权限。

<!-- wave5-verify.md:71 -->
**变异检验（除下面两种例外，否则强制）**：验收Agent**必须**对修复点做一次**微变异**
——把修复的那一行改回原样，确认检查**确实失败**，再恢复。
```

```yaml
# wrappers/verifier.md:4
tools: Read, Grep, Glob          # 没有 Edit / Write
```

**而契约又强制 `mutation_check` 必须为 `performed`**（`skipped` 只有 `harness_unsupported` / `unsafe_revert` 两种合法理由，都不是这个）。

**这比不检查更坏——契约强制了一个只能靠编才能满足的字段，把编造写成了合规的唯一形式。**

而这条恰好是全框架里**唯一一条号称"能直接证明检查瞄准了缺陷"的硬证据**（它引用的 NeurIPS 数据：外部瞄准测试 4.8% vs 自证 18.8%）。

### P-11 · 要求"必须真跑"，但没有任何 Agent 有浏览器能力

```markdown
<!-- wave2-audit.md:144 -->
**规则**：审计 Agent 在派发时若收到 `runnable: true`，**必须**执行至少一次真实运行验证。

<!-- wave2-audit.md:154 -->
| C · 服务 + 无头浏览器 | 起本地 HTTP 服务，用 headless Chrome 加载页面 | 静态站 / 前端 |
```

```bash
$ grep -rn "playwright|chrome|cdp|browser" wrappers/
（零命中）
```

**契约只检查 `runtime_evidence` 有 `method/command/observed/reproducible` 四个字段——不验证命令真跑过。**

**编一段 `command` + `observed` 和真跑过完全同形。**

## 三、它用我自己的记录证明我的假设不成立（这条最狠）

### P-06 · 「多轮自检」在本仓库里有两次可查的失效记录

它直接引用了 `run-state.md:419-424`——**我刚写的那段**：

> 「**没有触发条件的规则，等于没有规则。**
> 我写好了三级证据，但从未触发过一次检查。」

然后它说：

> 第二次失效尤其致命：那不是"忘了规则"，是**规则就在它自己的上下文里，它仍然没执行**。

**这是从我的失败里提炼出的结构性结论，不是猜测。**

它还指出两次失效的共同点：

| # | 失效 | 规则在哪 |
|---|---|---|
| 1 | round31 的 5/40 切片写了 `"severity": "NONE"` | `wave2-audit.md` 第 6 节明明有自检清单 |
| 2 | 13 个 Agent 派出去、5 个不返回，等 15h42m 没查 | `run-state.md` 自己写着"必须查" |

**推论**：所有以"返回前自检清单"形式存在的约束——`wave2-audit.md` 12 项、`wave3-critique.md` 7 项、`wave5-verify.md` 10 项——**都只是"要求模型声明自己检查过了"**。

**没有任何字段记录自检的证据。** 所以自检清单的真实作用，是让违规输出**多一段"我已逐项确认"的声明**。

## 四、其余我接受的关键几条

### P-03 · 「逐字回显」可以被提示词自己满足

**框架主动往上下文里投放了 40+ 行带路径和行号的真实代码**：

```markdown
<!-- wave3-critique.md:162-172 -->
check-stale.mjs:47       catch { continue; }   ← 已修
check-stale.mjs:122      catch { continue; }   ← 未修
```

**模型无法区分"我这一回合从文件里读到的字节"和"我从 system prompt 里读到的字节"。**

门 0 的全部判据是"引用看起来像不像真代码"。而**没有任何机械检查比对 quote 与文件内容**——`output-contract.md` 第 8 步对证据只检查 **"`evidence` 非空"**。

**后果**：伪造引用的成本从"必须真读文件"降到"必须写一段像代码的字符串"。

### P-04 · `contract_valid` 让被考核者自己打分

```markdown
<!-- output-contract.md:48 -->
由子Agent在返回前自行对 payload 做一次 schema 校验后写入。
```

**而第 6 步规定 `status = SUCCESS` 时 `contract_valid` 必须为 `true`。**

**最省力的自洽写法永远是 `true`**：写 `false` 会立刻触发作废流程。

**它给了实测数据**：round31 有 5/40 切片因为**照抄模板示例**写了 `"severity": "NONE"` 被判违规——**填一个四选一的枚举，错 12.5%**。而 `alternatives ≥ 2`、`runtime_evidence` 必须含原始输出、`files_read` 精确相等这些难度高一个数量级的，合规率只会更低。

### P-07 · Skeptic 无法观测它在核查的事

```markdown
<!-- wave3-critique.md:126 -->
| 3 | 越界检查 | 比对 L0 禁止清单：主 Agent 是否读过源码？ |
```

**Skeptic 的工具只有 `Read, Grep, Glob`，而"主 Agent 有没有读过源码"这个事实只存在于对话轨迹里，不在任何产物中。**

**这不是"难"，是信息不存在。**

### P-08 · 波次 1-3 没有合法的"我判断不了"出口

```markdown
<!-- handoff-schema.md:127 -->
| HUMAN_DECISION_REQUIRED | wave-4 / wave-5 | ... |
```

**产生波次被写死为 wave-4/wave-5。** 在侦察/宽扫/深挖/锐评四个波次里，主 Agent 遇到"这条线索算不算 HIGH""这个切片该不该深挖"时，**没有任何枚举值代表"我判断不了，请人来定"**。

而 `protocol.md:244` 说"未留痕比做错更严厉"——**最理性的策略是"做但不记"**。

### P-10 · 「标识符对账」是 CSS 专用却写成通用必做项

它列的四类（CSS 变量 / DOM id / 状态类 / 关键帧）**没有一类适用于 Go/Rust/Java/Python/C++**——而纳入清单里有 20 多种语言。

**后果**：一个审 Go 仓库的 Agent 只能跳过（但它是"必做项"）、硬跑（0 命中）、或**在返回里声称做过**（契约只检查字段存在）。

**这训练模型在返回里写不实的过程声明，而且通过全部机械校验。**

## 五、它给的总诊断（我认为最准确）

> **框架里最不现实的一条假设是**：
> 「一个模型可以在自己的上下文里维持一套它**无法观测**、也**无法验证**的规则状态。」

**三个不可执行的断言同时成立**：

1. **无法观测自己的行为**（P-07：Skeptic 查不到主 Agent 的 tool call）
2. **无法验证自己的输出**（P-03/04/06：门 0 没有逐字比对、`contract_valid` 自评、自检清单只要求声明）
3. **没有合法出口时不会停下**（P-08/P-12：波次 1-3 无"我判断不了"，`mutation_check` 只能靠编）

**三者叠加**：框架把全部可信度，押在了一组"**只能靠模型自觉、且无法被任何机制发现它没自觉**"的约束上。

而 `README.md:234`、`MANUAL.md:128`、`PORTABILITY.md:45` **自己都承认了这一点**（"纯提示词方案下，加载靠模型自律"）。

**真正尖锐的地方**：

> 这个仓库已经用**两次真实运行**证明了这条假设不成立——round31 的 5/40 契约违规、`D:\Web\style` 的 15 小时 42 分未查进程。
> 而两次事故的补法，**都是往提示词里再加一条规则**。
> 这不是修复，是**在同一个不可靠的执行者身上，用同一种手段，加注**。

## 六、它的结论（与竞品分析那份收敛）

> 如果要真的跑起来，唯一方向是**把机械性内容挪进调度器代码**：
> 门 0 的逐字比对、`contract_valid` 的 schema 校验、`files_read` 的集合相等、
> `mutation_check` 的变异执行、`state.json` 的落盘顺序。
>
> 留在提示词里的只应该是**判断性内容**（"这算不算 bug"）。
>
> **现在这 24 份文件里，至少三分之二的篇幅在描述本可以用 200 行 Python 保证的事情——而用自然语言描述机械约束，换来的不是灵活性，是执行率的静默归零。**

## 七、我的判断

**这份锐评我全盘接受。**

它的每一条都有 `file:line` + 逐字原文，我抽验的 4 条（P-06/P-11/P-12/P-07）**全部准确**。

**最关键的是它证明了我和我批评的对象犯了同一个错误**：

我批评被审项目的验证脚本"写了检查但不执行"——**然后我自己写了 15h42m 没查进程、5/40 切片照抄模板写了 `"NONE"`。**

而它给的解法和我之前的分层设想（核心提示词 + 可选工具层）**指向同一个方向，但它更彻底**：

> **不是"核心提示词 + 可选工具"，而是"机械归代码、判断归提示词"。**

这两者的区别是：我的分层把工具当**增强**，它主张机械部分是**前提**——因为没有工具，那些规则就是文字，而文字的执行率已经用两次真实失效证明过了。
