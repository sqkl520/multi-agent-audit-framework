## 二、已核实的三条致命项

### S1 · 「裁量留痕」的对账数据源是幽灵

```
$ grep -rn "wave2_completed" .
./MANUAL.md:307              ← 引用
./orchestrator/protocol.md:250  ← 引用
./templates/wave3-critique.md:124 ← 引用

$ grep -rn "wave2_completed.*:" .
（零处定义）
```

**它被引用 3 次、定义 0 次。** 不在账本字段里，不在 `state.json` 里——**是一个幽灵数据源。**

而且 Skeptic 的派发参数（`critique-panel:57`）是 `trace_id / round_id / critique_role / target_finding_ids`——**`discipline_log` 和 `state.json` 都不在其中**。`critique-panel:61` 更把它限定为"只看到审计发现的结构化字段"。

**而 `wave3:146` 规定 `discipline_audit.performed` 必须为 `true`，否则全部 `verdicts` 作废。**

### S2 · 复核者没有复核工具

```
wave3:125    mechanical_check 必须"用命令/脚本独立验证"
protocol:248 它是唯一被授权做机械比对的角色
critique-panel:4  tools: Read, Grep, Glob     ← 没有 Bash
```

L1 五类裁量（预算截断 / FIFO 重排 / 维度指派 / 可达性排序）的复核需要 `wc -l`、`ls`、`git log`、`comm`——**全部要 Bash**。

**§1.3 那张判定表里"mechanical_check 可执行"这一列，在真实 harness 上没有执行者。**

### S7 · 攻击清单由被攻击者撰写（最深刻的一条）

```markdown
<!-- wave2-audit.md:499 -->
## 第 5 节：与锐评波的前置对齐——审计Agent必须为 Skeptic 留下攻击面

<!-- wave2-audit.md:510 -->
Skeptic 可以直接使用这些替代解释作为攻击方向。
```

```bash
$ grep -n "alternatives.*之外|清单之外|自行构造.*替代" templates/wave3-critique.md
（零命中）
```

**被告先生成"我这条发现最可能错在哪"（`inference.alternatives`），原告照着这份清单攻击。**

**全框架没有任何一条要求 Skeptic 找出清单之外的替代解释。**

而 `wave3:37` 的成功标准是**"移除了多少"**——

> 一个只攻击被告自认弱点的 Skeptic，**既满足了 KPI，又从不触及被告没承认的弱点**。
> 这是一个**双方都最优、审计质量最差**的均衡。

**还有一个我没想到的后果**：`wave2-audit:510` 说"如果审计 Agent 没提供足够的替代解释，Skeptic 会返回 `EVIDENCE_GAP`"——于是 `alternatives ≥ 2` 变成了**免疫机制**：写得越"周全"，越不会被打回。**它激励的是"把最可能的三个真实漏洞写进 alternatives，让它们被'已经考虑过了'"。**

## 三、其余我接受的几条

### S6 · 「默认路径没有理由跑不完」是假的

```markdown
<!-- protocol.md:151 -->
默认路径**没有理由跑不完**（全只读，无回滚、无副作用、**无人工裁决触发点**）

<!-- handoff-schema.md:154 -->
| 人工阻塞 | HUMAN_DECISION_REQUIRED、REVOKED | 不能自动消解 | 本轮状态为 PARTIALLY_CLOSED |
```

**`REVOKED` 是 Arbiter 在默认路径内自动产出的结果**，却被归入"人工阻塞（不可自动消解）"。

**所以：框架自动生产出的每一个 `REVOKED`，都永久占据一个"只能由人清除"的槽位。**

推论：**只要 Skeptic 成功撤销过一条发现，本轮必然 `PARTIALLY_CLOSED`，不可能 `CLOSED`。**

而 `protocol:151` 那句「无人工裁决触发点」是本轮把修复移出默认路径的**全部论据**——**它被自己的锐评波反驳了。**

round31 实测 `REVOKED 41`——**按此设计，那一轮无论修不修，都不可能 CLOSED。**

### S10 · 引用了"选择性触发优于无条件 debate"，然后自己做无条件触发

```markdown
<!-- wave3-critique.md:14 -->
**本波次的设计取向是「证伪」而不是「辩论」，且只在存在真实冲突时才扇出**
——这三条外部证据共同支持本波次瘦身
```

但下游三处全部无条件派发：`scale-mapping:68-70` 按切片档位**固定**分配，`protocol:307` 要求 DA 必须 SUCCESS，`README:44` 三方都写成必需。

**全框架没有任何一处定义"什么算真实冲突"。**

> 这不是"引用与实现有偏差"，是**它自己引用的反面证据精确预言了它自己的失效模式**。

### S13 · 唯一被验证过能产出真发现的路径，是框架已经不用（且从未验证）的那条

**这条是对我冲击最大的。**

`docs/analysis/README.md` 记录了"可复现的真发现"：`S04` 的 `--rot`/`--r`、`M02` 的 CSS 解析、11 个 CSS 文件的配对。

**它们全部产生于只有 2 个深挖 agent 的单遍流程。**

> **有产出的是简单路径，被验证的是简单路径；所有后来加的波次（宽扫、可达性、裁量留痕、Arbiter、五波门控）的边际贡献是 0 条可核实发现。**
>
> 框架对自身的全部"改进"记录**没有一条来自实测收益**，全部来自"修矛盾"。
> **一个只靠修矛盾增长、从不靠增益增长的系统，其净收益是负的且不可证伪。**

### S4 · 「只加载结构化摘要」被它自己的加载计划证伪

按 `README:245` + `MANUAL:70`，主 Agent 常驻：

```
protocol.md(383) + scale-mapping.md(302) + final-report.md(371)
+ run-state.md(446) + round-detection.md(141) + report-naming.md(117) = 1760 行
```

**这些不是"结构化任务描述和结果摘要"，是带论证、带事故复盘、带自我辩解的长篇散文**（`run-state.md` 整节是 15h42m 事故复盘；`scale-mapping` 是 28 行算术陷阱自白）。

> 「隔离」实际达成的不是"主 Agent 上下文干净"，而是**把原来分散在代码里的判断，压缩成了一份常驻的 1760 行规则**。规则本身是散文，就必然被以散文方式理解——**这正是它声称要消除的漂移来源。**

### S16 · 维护成本已经超过被维护对象

```
framework/        6114 行
docs/analysis/    3517 行   ← 元层已达被评对象的 58%
```

而元层自己的 18 份里有 3 份被判"已被取代/部分作废/需谨慎"——**16.7% 的自产文档在被写出的 2 天内失去可信度**。

> 这与它批评框架的病灶完全同构：「每修一处，就多一处未同步的副本」这句话对元层同样成立。

## 四、它给的最致命一条（我完全接受）

> **「裁量留痕」的复核链是断的，而框架把整轮结论的有效性押在这条链上。**

三个断点，每一个单独都足以让它不成立：

1. **对账的另一半不存在**：`wave2_completed` 引用 4 次、定义 0 次
2. **对账的人拿不到材料**：Skeptic 的派发参数里没有 `discipline_log` 和 `state.json`
3. **复核者没有复核工具**：`Read, Grep, Glob`，而要求"用命令/脚本验证"

> 结果是：Skeptic 要么诚实地产出 `log_entries_checked: 0`（而按 `wave3:149` 会被读成"零裁量"），要么填一个数字（该数字无人校验）。

**它的结论我完全接受**：

> 「从零裁量改为裁量留痕」这个修订，实际完成的只有一件事：
> **把一个"无法执行"的规则，换成了一个"无法验证"的规则，同时保留了"违反即该轮作废"的惩罚。**
>
> 它比原来更坏——原来主 Agent 至少知道自己违反了规则，**现在它可以合法地、逐条地写下一份关于自己如何合规的叙述，而全框架没有任何一处能发现那份叙述是空的。**
>
> **这就是 `evidence-policy` 门 0 在它自己身上的失败：主张（`discipline_log`）有，可核验的原文引用（`wave2_completed` 的实际记录）没有。**

## 五、这份锐评对我的意义

**它是唯一一份直接移除「净收益为正」这个前提的。**

其他 12 份说"这个环节该换工具""这条规则有矛盾""这个成本算错了"——**都还默认"修好之后这套东西是有价值的"。**

**S13 说：不是。** 唯一有产出的路径是你已经不用（且从未验证）的那条。后面加的一切，边际贡献是 0 条可核实发现。

**这个判断我目前无法反驳。**

因为可核实的证据确实都来自单遍流程：
- 第 1 轮：2 个深挖 agent → 29 条发现（含 S04 那条阻断级）
- 第 2 轮：5 组并行 → 52 条有产物的发现
- 而 round31（唯一跑过完整五波次的）→ **1 条修复、没有最终报告**

**两遍制、可达性、裁量留痕、Arbiter——这些我花了几十轮加进去的东西，一条可核实的发现都没产出过。**
