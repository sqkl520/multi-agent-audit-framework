# 行为准则

## 简短版

直率、友善。讨论工作，不讨论做工作的人。

## 适用范围

适用于 issue、pull request、commit message、代码注释，以及任何你代表本项目发言的渠道。

## 期望的行为

- **批评产物，不批评作者。** 「这条规则永远不触发，因为正则匹配不到 X」是好的；
  「写这个的人根本没动脑子」不是——而且在这个仓库里通常也判断错了：
  历史里满是「写得很认真、却依然没有触发」的规则，因为**写一条规则**和**强制执行一条规则**是两件事。
- **带着证据来。** 这个项目的文化是数字优先于断言。如果你说某道闸门坏了，请给出输入和输出。
- **首次接触时假设对方是善意的。** 尤其涉及翻译内容时：框架文档的主要语言是中文，
  而细微差别在机器翻译里存活得不好。
- **尊重范围边界。** 关于某个**被审计目标仓库**安全性的报告，属于那个项目，不属于这里。

## 不可接受的行为

骚扰、人身攻击、歧视性言论、蓄意恐吓、公开他人隐私信息，以及持续扰乱讨论。

另外：**不要把别人的凭据或隐私数据**贴进 issue、PR 或公告——哪怕是为了演示泄漏。
一个前缀加一个提交哈希就够了。

## 执行

请通过 GitHub 主页上的地址联系维护者，或在报告本身敏感时开一个私密公告。
报告会被阅读，回复会说明做了什么——不会静默处理。

后果随严重性与重复次数递进：要求改写措辞 → 删除评论 → 临时封禁 → 永久封禁。
任何处理涉及自己的举报的人应当回避。

## 关于来源

这是一份简短的、项目自定的准则，而不是采用某个模板（Contributor Covenant 之类）。
如果项目发展到不止一个维护者，采用标准模板并建立正式治理会是正确的下一步——
本文档不假装自己是那样的东西。
