# 门 0 伪造手法实测：10 种攻击，9 种被挡、1 种暴露规范空白

**日期**：2026-11-12
**方法**：造一个含「安全函数 + 不安全函数」的仓库，然后用 10 种手法伪造引文，看 `verify-artifacts.mjs` 的门 0 能挡住几种。

**为什么做这个**：上一轮测的是「契约合规」这个标签，这一轮测的是**更底层的证据真实性**。门 0 是整个框架反捏造的地基——如果它能被绕过，上面所有检查都是在流沙上盖楼。

## 缺口：注释被当成证据

**手法**：不伪造任何东西，直接引用源码里的一行注释。

```js
// 第 13 行
// 不安全版本：容量检查写错
```

```json
{ "evidence": { "file": "src/queue.js", "line": 13, "quote": "// 不安全版本：容量检查写错" } }
```

行号准确、引文逐字存在。**旧版门 0 判 PASS。**

**为什么这是问题**：注释是作者对代码的**描述**，不是代码的**行为**。一段写着「这里没做校验」的注释，可能描述的是上一版代码；一段写着「容量检查写错」的注释，可能是作者的自我提醒。

用注释证明代码有问题，等于把「人说它有问题」当成「它有问题」——而门 0 的全部意义正是「不要相信说法，要看代码」。

**根因是规范空白**：`evidence-policy.md` 全文没有一个字提到注释。校验器只比对文本，不区分注释和代码。所以这不是实现 bug，是**规则没想到这种情况**。

---

## 修复：加了规则，也加了豁免

**规则**写入 `evidence-policy.md` §5：

- quote 是纯注释行、用来支撑代码缺陷 → **门 0 失败**
- quote 是代码行（含行尾注释）→ 通过
- 缺陷本身是「注释与实现不符」→ **通过**

**实现**在 `verify-artifacts.mjs` 的 `isPureCommentLine()`，覆盖 `//`、`#`、`/* */`、`--`、`<!-- -->`、`"""`；同时用 `discussesComments` 判断 inference 是否在讨论注释本身。

---

## 三次差点做错

### 第一次：豁免判据太宽，等于没修

最初 `discussesComments` 的正则是 `/注释|JSDoc|@returns|@param|文档说|注释声称|注释写/i`。

问题是它匹配**任何含「注释」二字的句子**——包括攻击者的 `basis: "注释说这里不安全"`。

**结果：攻击照常通过。** 我一直以为修好了，直到单独测试才发现。

改成只认「把注释当被审对象」的句式：`注释(与|和)(实现|代码|行为)不符`、`注释声称`、`JSDoc 声称`、`声明...未兑现`。

**教训**：豁免条件比拦截条件更容易写坏，因为它看起来是「在做好事」。**每一条豁免都必须配一个「应当被拦」的反向用例**，否则豁免会静默吞掉整条规则。

### 第二次：测试用例选错，掩盖了缺口

一开始只写了 06（引注释 + 行号错）。它被判 FAIL，我就以为注释规则生效了。

实际上它是被**「行号不符」**这条老规则拦下的，压根没走到注释判断。

直到补了 06b（引注释 + 行号**对**），才暴露出真实缺口。

**教训**：一个「攻击被拦住」的结果，要问清楚**是被哪条规则拦的**。如果是被无关的规则顺手拦下，那个攻击其实没有被真正测试。

### 第三次：改文档把 lint 弄红了

`evidence-policy.md` 是 `audit-specialist` 的启动必读文件，L16 限制 1700 行。我加了一版 17 行的说明，直接把加载量顶到 1711。

压了三轮（1711 → 1705 → 1703 → 1701 → 通过），最后靠把表格改成分点列表才腾出空间。

**这件事本身说明 L16 是对的**——共享文件确实在承载不属于每个角色的内容。但当下我只想加一条规则，就撞上了上限。

## 还剩什么没被攻击过

这轮只测了**引文本身怎么伪造**。还有三类完全没碰：

1. **`inference.alternatives` 的敷衍填充**——契约要求「推断可推翻性」，但塞一个 `["可能是故意的"]` 就满足了。没有测过什么样的 alternatives 才算真的考虑了替代解释。
2. **严重性定级**——同一段代码，标 CRITICAL 还是 LOW，目前没有任何机械约束。一个 agent 可以把所有东西都标 CRITICAL，或者都标 LOW。
3. **`searched_scope` 的真实性**——agent 声称读了 7 个文件，谁能证明它真读了？门 0 只管 quote 真不真，不管「范围声明」真不真。这是**最后一个可以整段编造而不被发现的字段**。
