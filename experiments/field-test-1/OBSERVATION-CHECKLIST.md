# 实战验证观察清单（field-test-1）

**时间**：2026-11-15
**素材**：Hilltop Village `shop` 模块的 7 条真实未修缺陷（R3-C F1–F7）
**目的**：验证 R1–R21 加的所有闸门**在真实任务上是否会误拦正常操作**

---

## 为什么选这 7 条

1. **真实**：来自那次真实审计的产物 `out/round3-C-audit.md`，不是我编的
2. **有已知答案**：7 条都裁决为 UPHELD，都该修
3. **难度适中**：3 个文件、严重度 MEDIUM×3 + LOW×4
4. **天然触发并发约束**：F1–F4 同在 `ShopConfigLoader.java` → 必须串行组；
   F5 独立；F6/F7 同在 `CommandsGenerator.java` → 串行组。
   **这是 3 个串行组、组间并行的真实场景**，正好检验 R5 的「实例唯一性」规则会不会被误读
5. **仓库本来就是脏的**（25 项改动）→ 正好检验 R20 的 `fix_baseline`

---

## 要盯的六件事

### 1. 并发：会不会派 7 个实例？

诊断的核心发现是「修复阶段 0 次 subagent」。
现在任务书里明写了派发要求 + 文件级依赖分析规则。

**观察**：`budget.spawned_fix_agents` 是多少？实际有没有 3 个组？
**误拦风险**：R5 说「一条 finding 一个实例」，但 F1–F4 同文件必须串行——
如果 agent 理解成「4 条必须 4 个实例但串行」，vs「4 条编进 1 个串行组」，
哪种合规？R5 的文档写清楚了吗？

### 2. 基线：`fix_baseline` 抓对了吗？

仓库现在有 25 项改动，其中 16 个已跟踪修改 + 9 个未跟踪（8 个 `.java` + `repair-artifacts/`）。

**观察**：它抓的 `dirty_paths` 是不是这 25 项？
如果它只抓了部分，或者抓完立刻自己又改了文件，基线就失真。
**误拦风险**：R19 的 `underreported` 会不会因为基线不准而把「修复前就脏的文件」全报出来？

### 3. `target_repo` 指向对吗？

**误拦风险**：如果它填的是相对路径、或者填了产物目录而不是被审仓库，
`check-payload` 的所有路径解析都会失败，然后报一堆 `*_not_found`。

### 4. `files_touched` 与 harness 记录对得上吗？

这是 R21 的新规则。真实场景下：
- 实例会写测试文件吗？（修 F1 可能新增 `ShopConfigLoaderTest.java`）
- 如果它写了测试但没登记在 `files_touched` 里 → `underreported_by_harness` 会 FAIL
- **这算误拦吗？** 我认为不算——`files_touched` 本来就该包含测试文件。
  但如果 `output-contract/fix.md` 没说清，就是文档缺陷。

### 5. 红测日志：真的会生成吗？

R11/R17 要求 `red_log_path` 存在。真实场景下：
- 修复前跑测试确认 FAIL → 那个输出要重定向到文件
- **误拦风险**：如果 agent 只是「心里知道是红的」而没有真的跑并保存日志，
  它会被 `red_log_not_found` 拦住。**这恰恰是规则该做的**——但会不会导致它卡住无法完成？

### 6. 相位闭合的六道门会不会太严

`stop-hook` 在 wave4 现在有 6 道判据：
1. `current_plan` 存在
2. 多缺陷多实例（`spawned_fix_agents > 1`）
3. harness 对账（实际 subagent 调用数）
4. 产物有信封
5. `dir_path` 存在且非空目录
6. `check-payload` 逐份字段校验
7. `files_touched` ↔ write/edit 对账

**误拦风险**：真实任务中很可能某道门因为它没做某件「框架要求但任务书没强调」的事而 FAIL，
导致它反复重试卡死。

## 判定标准

| 现象 | 判定 |
|---|---|
| 闸门拦住了一个真的违规 | ✅ 规则有效 |
| 闸门拦住了正常操作，agent 明确说明「这是误拦」并给证据 | ✅ **有价值的发现**，要修规则 |
| 闸门拦住了正常操作，agent 想办法绕过让它变绿 | ❌ **最糟**——说明规则设计有问题且被规避 |
| 闸门根本没触发（全绿通过了） | ⚠️ 要查是真合规还是判据没跑 |
| agent 卡死/超时 | ⚠️ 要查是哪道门 |
