# 决定：A 不作为闸门上线，改用三条零误报的对账

**时间**：2026-11-17 05:50
**依据**：原型 agent 的完整实测规格（`proto/check-test-assertion-diff.mjs`，97 文件 / 2733 调用点）
+ 红队对方案的逐条攻击（`REDTEAM-plan-fake-checks.md`）。

---

## 原型 agent 的判定，我采纳

它说**不该作为闸门上线**，理由是它的成绩单与它的射程不是一回事：

| 指标 | 实测 |
|---|---|
| 「已有测试的 expected 反转」这一类精确率 | **2/2 = 100%** |
| 同一类召回率 | **2/2 = 100%** |
| 定标陷阱（处 3：改名+保留断言） | **0 误报** |
| 全量 27 改动文件噪声 | **0** |
| **删整个测试方法** | **63.2%**（基线 HEAD）／100%（基线换成上一轮快照）|
| **新增测试文件的任何弱化** | **0/19，45.0% 的断言结构上不可检** |
| **F1 形态** | **0 命中**，无论有无基线 |

**它精确抓到的那一类，在 27 个文件里只有 2 条，而且这 2 条是合法的。**

> 一份 100% 精确、100% 召回、但只覆盖 0 个真实缺陷的检测器，不能当闸门：
> 它会把一次「全部通过」变成一个没有依据的绿灯，**而这比什么都不做更糟**——
> 它给了人一个「已经查过了」的错觉。

这与本诊断的主题是同一件事：**一个会亮的绿灯，比没有灯更危险。**

---

## 但它的三条硬约束我全部记下了

如果将来要上线，缺一条就不合格。其中两条推翻了我先前的判断：

### 1. 基线必须是**上一轮快照**，不是 HEAD —— 这条最重要

实测：留一法召回完全由基线口径决定。

```
baseline = HEAD        → 24/38 = 63.2%
baseline = 上一轮快照   → 38/38 = 100.0%
```

原因：work 的断言数已是 HEAD 的 1.21 倍（331 vs 274）。在 HEAD 基线下删掉一个测试方法，
该文件的断言数仍可能不低于 HEAD，于是 subject 规则和计数规则**双双失效**。

**这条我先前完全没想到。** 我一直在用 HEAD 做实验，得出「删方法只召回 55.3%」，
而那个数字的成因一半是基线选错。

### 2. `@Disabled` 带参同样是禁用 —— 这是方案的事实错误

> JUnit 5 的 `value()` 是**可选原因**，不是条件。`@Disabled("flaky")` 与裸 `@Disabled`
> 对测试是否执行**完全等价**。

方案说「只有无参 `@Disabled` 才触发」，会漏掉最常见的禁用形态。
真正该排除的是 `Assumptions.assume*`（合法的条件跳过，语料里 6 处）。

### 3. `expected` 必须用**多重集**，且规则 2 必须按**方法作用域**

- 多重集：留一法召回 55.3% → 60.5%，真实集仍 0 误报。集合比较会漏「同一方法里两条相同期望、删一条」。
- 方法作用域：实测 7 个被改文件，HEAD 签名集**全部**是工作区签名集的子集（7/7）。
  **文件级比较下规则 2 永不触发，真实定标的 2 处反转在文件级读数是 0 命中。**

## 原型 agent 指出的第三条替代方案，框架里已经有了

它建议：**`TEST_CONFLICT` 双向对账** ——
「修复者说没动测试，而 `git diff` 显示测试变了」这一条自相矛盾，
不需要解析断言，只需比对 `files_touched` 与 `git diff --name-only src/test`。

**`tools/stop-hook.mjs` §3.7.6 已经在做这件事**（`:984-1010`）：

> `overclaimed` claimed − actual 非空 → FAIL
> `underreported` actual − claimed 非空（**过滤后**）→ 源码 FAIL / 非源码 WARN

所以不需要新工具。**缺的只是「测试文件必须进 `files_touched`」这个契约要求**——
而 `wave4-fix.md:335` 已经写了「写权限边界：`files_touched` 全部在 `target_files` 或对应测试文件内」，
但它只说「不许越界」，**没说「改了测试就必须登记」**。

---

## 我的决定：做三件零误报的小事，不做那件 63.2% 的大事

| # | 做什么 | 误报 | 覆盖什么 |
|---|---|---|---|
| 1 | **测试文件必须进 `files_touched`**（契约 + 已有 §3.7.6 自动执行）| **0** | 删方法 / 改名 / 加 `@Disabled` 三种形态全覆盖——只要测试文件被动过就必须登记 |
| 2 | **`@Disabled` 带参算禁用**（写进 `wave4-fix.md:200` 的禁止清单）| 0 | 最常见的禁用形态 |
| 3 | **`input_space_basis` 申报**（本轮已实测：全仓 0 个测试遍历截断点 → F1 不是「加弱测试」，是「从没测过」）| 0 | F1 形态——**唯一可行的抓手**，因为它不需要 diff |

**为什么是这三件**：它们都不需要断言解析，因此没有「新增文件 45% 不可检」那个洞。
